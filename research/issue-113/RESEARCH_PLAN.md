# Issue #113 — verified provenance authenticity

Baseline: merged `main` `16a6a11920ff232e8101b9cb6a8382d52868a206`, immediately after #111.

## Research findings

### Canonical authority

`pseudepigrapha_tf.provenance` already owns the source/license truth contract. Distribution must consume it, not duplicate OCP license constants.

For a clean, independently attested checkout of the pinned source tuple

- repository: `https://github.com/OnlineCriticalPseudepigrapha/Online-Critical-Pseudepigrapha`
- commit: `c939dcbacad78c5d18d2c4282cad23c47e19ac07`

`corpus_license_metadata(..., source_identity_verified=True)` requires:

- `converterSoftwareLicense = MIT`
- `sourceIdentityStatus = verified`
- `contentLicenseStatus = verified`
- `contentLicense = CC-BY-4.0`
- `contentLicenseUrl = https://creativecommons.org/licenses/by/4.0/`
- `contentLicenseSource = <OCP repository>/blob/c939dcb.../LICENSE.CC-BY-4.0`
- `contentLicenseScope = OCP text editions and TEI XML files under static/docs/`
- `upstreamSoftwareLicense = GPL-3.0`
- `upstreamLicenseCommit = 8c8c2c55a2c55ba4b23ac506956f98dcc25045b2`
- the exact OCP content attribution string
- the exact OCP content citation string
- no source-identity diagnostic
- no content-license diagnostic.

Repository/commit select the profile; `converterVersion` is publication identity checked separately by `distribution.py`.

`corpus_license_provenance_is_consistent()` already fails closed when expected profile values are missing/wrong, when verified-only values are overclaimed for an unverified/unknown profile, or when verified states carry diagnostics. An unknown repository/commit with source identity marked verified obtains canonical `contentLicenseStatus=unverified`, so it cannot legitimately claim a verified corpus license.

### Production path

The CLI builds graph metadata, independently detects the source checkout, then calls `attest_corpus_license_source_identity()` before `build_conversion_report()` and before Text-Fabric serialization. The report is projected from the same generic metadata via `report_provenance()`. The Text-Fabric writer serializes that generic metadata into feature headers, including `otype.tf`.

Exact pinned full-corpus integration run `34284414744` on #111 already passed conversion, canonical staging/manifest validation, stock TF extraction/reload, public metadata, and advanced app startup. A dedicated isolated corroboration run `34289983075` was launched from immutable research commit `0d3cf423e9835bbed3e941409e5871fb6e93db2c`; it directly compares the generated report projection, serialized `otype.tf` projection, and `corpus_license_metadata()` expected projection and asserts profile consistency. **Do not enter TDD until that run succeeds.**

### Existing gap

After #111, `_report_identity()` proves required verified statuses and rejects contradictory diagnostics, then `_validate_serialized_identity()` proves report ↔ serialized canonical-field equality. Neither step proves that the mutually agreeing values are the canonical researched profile. Therefore a handcrafted archive/report pair can agree on `contentLicense=OTHER`, an invalid URL/license commit/software license, omit verified-only attribution/citation evidence, or claim a verified license for an unknown tuple and still pass if hashes are recomputed consistently.

## Plan

1. Keep `REPORT_PROVENANCE_FIELDS` as the only report ↔ Text-Fabric key mapping.
2. In `_report_identity()`, finish constructing/validating the existing `serialized_provenance` projection from report provenance.
3. Reconstruct generic metadata by reversing that same mapping; do not add a new field registry.
4. Pass the generic projection to `corpus_license_provenance_is_consistent()`.
5. If false, fail manifest construction with a specific canonical-profile diagnostic.
6. Keep #111 representation equality as a separate later invariant; authenticity and representation equality must both hold.
7. Keep `version`/converter-version checks separate and leave arbitrary non-canonical Text-Fabric metadata untouched.
8. Do not alter ordinary conversion or allow/deny unverified internal graphs here; this check exists only at the canonical publication boundary.

## RED design

Use a synthetic otherwise-valid archive/report pair built from the canonical profile generated by `corpus_license_metadata()` itself, so tests do not duplicate expected license constants.

RED cases will make report and `otype.tf` agree while:

- mutating each profile value that current distribution merely requires to be non-empty;
- omitting each verified-only field that current distribution treats as optional;
- changing to an unresearched repository/commit while retaining a forged verified OCP-like license profile.

Positive controls:

- the exact canonical profile passes;
- extra non-canonical TF metadata such as `writtenBy` passes.

The pre-fix branch must fail only the new reject assertions. No production change is allowed before this RED is observed in CI.
